## Database status

Migration `20260828000000_add_clinic_advisor_storage` was inspected before execution. It is additive and idempotent: it creates Advisor conversation, message, memory, memory-clinic, memory-job, audit, and recommendation storage; it does not alter or drop existing product tables.

The dedicated **RivaCare Database Migration Runner - MANUAL** executed the migration successfully as manual execution `101801`. Read-only verification then confirmed all required tables, columns, indexes, constraints, UUID primary key, tenant foreign key, and composite tenant/clinic foreign key. Prisma's migration ledger was safely baselined with `migrate resolve --applied` after that independent verification; `prisma migrate status` now reports the schema up to date.

Follow-up migration `20260903000000_scope_advisor_memory_jobs` closed a tenant-isolation gap: memory jobs were tied to conversations but did not persist `tenant_id`. It is additive and fail-safe: it backfills from the owning conversation, aborts if any existing row cannot be attributed, then enforces a non-null tenant column, tenant FK, composite message/conversation/tenant FK, and tenant/status claim index. The authorized runner applied it in manual execution `103310`; verification execution `103312` confirmed every expected column, constraint, index, and tenant match with no unscoped rows. It was then recorded in Prisma's ledger; live `prisma migrate status` reports the two-migration schema up to date.

Tenant-owned Advisor records contain `tenant_id`. Clinic-owned recommendation and memory-scope records use composite `(tenant_id, clinic_id)` foreign keys to `clinic_configs`. Runtime SQL binds parameters rather than interpolating request values.

### Retell routing architecture correction (2026-09-03)

The operator confirmed the intended vendor-facing architecture is **Retell → n8n → dashboard/Juvonno**, not Retell → BFF → n8n. The reviewed v12 Retell export now correctly retains the direct n8n URLs: all seven custom functions target `/webhook/juvonno-receptionist`; agent-level `call_analyzed` targets `/webhook/juvonno`; and the attached phone number must use `/webhook/retell-inbound-clinic-router`. The inbound router's destination-phone lookup is the tenant/clinic authority and may return the separately configured clinic agent as `override_agent_id`; that ID is never tenant authority.

The operator confirmed the Retell-side direct-n8n configuration is in place. The Receptionist workflow is now active at version `15f44698-c5af-4561-8b4f-d5a86d7193a8` and the INBOUND workflow at version `5719ebcd-0927-49dd-b0bc-427f0ee48902`. The BFF `GET /api/dashboard/outbound-batches` and `GET /api/dashboard/outbound-batches/:id` routes now require owner/admin. Payment Recovery financial mutations are now owner/admin-only at the BFF: queue approval/rejection, invoice hold/resume/escalate/reconcile, and recovery settings changes all apply `requireRole('owner', 'admin')` after the session, CSRF, and clinic-access checks. Its saved, unpublished sync draft now logs and skips rows missing tenant/clinic identity or a Juvonno domain/key, allowing configured clinics to proceed without an incomplete clinic terminating the batch. It remains unpublished pending a controlled end-to-end validation.

Appointment Request queue mutations now use the same owner/admin boundary. Approve, reject, assign, and archive operations require session, CSRF, verified clinic access, and `requireRole('owner', 'admin')`; read-only queue/activity routes retain the existing clinic-scoped access policy.

An active-workflow trigger audit confirmed Header Auth on every webhook of Settings, Outbound, Appointment Requests, SMS Follow-Ups, hardened Outbound Batches, and Manager Analyst Tools. The intentionally inactive Inbound, Receptionist, Payment Recovery, migration runner, and legacy batch workflow are excluded from this active-webhook result.

The BFF now recursively redacts credential-shaped keys from the public Settings response, including nested legacy `api_key`, token, secret, password, authorization, account-SID, and webhook-key fields. The n8n public query already avoids encrypted columns; this adds a second boundary against historical JSON configuration leakage.

Knowledge Base website submissions now require an ordinary public HTTPS hostname. Credentialed URLs, localhost/local-only names, and IPv4/IPv6 literals are rejected before queueing, preventing the dashboard from supplying an obvious internal or metadata target to a future retrieval worker.
